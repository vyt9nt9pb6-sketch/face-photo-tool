# 视频查重去重工具（video_dedupe）

本地运行的**全盘视频查重**工具。找出重复的视频，按**画质最好**的一份保留，其余同盘移动到指定目录，并生成可还原的清单。不上传、不联网、不删除。

和同仓库的 `face-photo-tool`（照片查重）配套使用，两者的「只移动不删除 + 清单可还原」策略一致。

---

## 为什么不能只比文件大小

同一段视频在不同设备/不同导出流程下会得到尺寸相同但字节不同的文件：

- 同一个片段被导出成不同码率（同一画面，体积差几倍）
- 同一段视频被重命名后散落在不同备份目录
- 手机「最近项目」里存的是编辑后的副本，和「相机胶卷」里的原片内容一致

所以判重分三层，从便宜到昂贵，逐层收窄：

| 层 | 手段 | 能回答什么 | 代价 |
|---|---|---|---|
| 1 | 体积 + 头/中/尾三段采样哈希 | 字节几乎必然相同（极低概率误判） | 每文件读 3×256 KB |
| 2 | 完整 MD5 | 字节完全相同 | 全量读盘 |
| 3 | 时间轴抽帧 + 旋转不变帧差 | 是否**同一段画面**（重编码/改名/不同码率） | 解码，4K HEVC 很慢 |

## 安装

```bash
python -m pip install -r requirements.txt
```

`opencv-python` 用于解帧。没有它时第 1、2 层仍可正常工作，第 3 层跳过。

## 用法

### 1. 建索引

```bash
python vindex.py --root /path/to/videos --out vindex.pkl
```

只算体积和采样哈希，很快（几百个文件几十秒）。

### 2. 字节级确认

```bash
python md5check.py --index vindex.pkl --out exact.json
```

把「采样哈希相同」的组拿出来做完整 MD5，输出真正字节一致的组。这一步能直接定案大部分重复。

### 3. 画面级确认（可选，慢）

对剩下的可疑对（体积接近、分辨率相同、时长相近）抽帧比对：

```bash
python frames.py --index vindex.pkl --exact exact.json --out frames.json
```

每个候选对抽 8~12 帧，按**统一时间轴**取点，逐帧取 4 个旋转方向的灰度平均差最小值，再用逐帧差的**中位数**判定。

判读标准：

- `med ≤ 1` 且 `corr ≥ 0.99` → 同一段画面
- `med` 在 1~5 → 疑似，人工看一眼
- `med > 5` → 不同片段

### 4. 生成移动计划

```bash
python decide.py --index vindex.pkl --exact exact.json --frames frames.json \
    --dup-dir ./重复视频 --out plan.json
```

按簇合并（字节相同 / 帧比对确认 / 同名同码率族），每簇按画质排序保留一份，其余进计划。**只输出计划，不动文件。**

### 5. 执行

```bash
python apply.py --plan plan.json --dup-dir ./重复视频 --index vindex.pkl
```

同盘 `shutil.move` 是即时改名，不占额外空间。生成 `video_dedupe_manifest.csv`（原路径 / 新路径 / 保留路径 / 字节 / 分辨率 / 时长 / 帧率 / 说明）。

### 6. 还原

```bash
python restore.py --manifest video_dedupe_manifest.csv
```

把移走的文件按原路径搬回。

## 保留哪一份

排序键，从高到低：

```
像素数(宽×高) → 码率(体积×8/时长) → 文件体积 → 目录层级浅
```

**不能用时长做画质维度**。实测踩过：一段 4K 视频有一个 24fps 低码率版本时长略长，按「时长优先」会保留体积更小、更糊的那份。

---

## 三条实测教训

这些是真实踩坑后写进代码的约束，改参数时要留意：

1. **同名不等于同一段**。`IMG_8027` 两个版本时长差 0.69 s（6.93 vs 7.62），画面范围不同，强行合并会丢内容。因此 `decide.py` 规定**时长差 > 0.5 s 一律不合并**（`--max-dur-diff`）。

2. **抽帧必须按时间轴，不能按帧序号**。不同版本帧率不同（24/30/60 fps），按 `CAP_PROP_POS_FRAMES` 取「第 N 帧」会落在不同时刻，比对结果全错。代码统一用 `CAP_PROP_POS_MSEC`。

3. **旋转副本要单独处理**。手机导出的视频有竖拍旋转标记，同一段画面旋转 90° 后逐点比较差异巨大。帧比对对每个候选取 4 个旋转方向的最小值。

另外：4K HEVC 解帧非常慢（每文件十几秒），几百个文件全量跑要几小时。建议先用第 1、2 层把范围压到几十对，再跑第 3 层。

## 目录

```
vindex.py     建索引（体积 + 采样哈希 + 可选帧指纹）
md5check.py   字节级全量 MD5 确认
frames.py     时间轴抽帧的旋转不变画面比对
decide.py     合并成簇，按画质选保留项，出移动计划
apply.py      执行移动，写可还原清单
restore.py    按清单还原
```
